# Testing and the dashboard

## Layers (strategy 4.1) and how to run them
All commands run inside WSL (the C tree builds there).

| Command | What it does |
|---------|--------------|
| `scripts/c_check.sh` | build + every test, plain then ASan+UBSan |
| `scripts/c_tsan.sh` | whole suite under ThreadSanitizer |
| `scripts/c_coverage.sh` | gcov line coverage per component and file (`scripts/cov_missing.sh <path>` lists untested lines) |
| `scripts/c_lint.sh` | banned functions, licences, `gcc -fanalyzer` |
| `scripts/g5c_regress.sh [--oracle]` | everything above, layer by layer, plus the conformance-matrix check, the performance gate, soak figures and (with `--oracle`) Open5GS + UERANSIM scenarios S3/S4 against our NFs, our SMF and our AMF (S3-S5). Summary in `build/regress-summary.txt` |
| `ctest -L <layer>` | one layer: `unit`, `component`, `integration`, `conformance`, `fuzz`, `perf`, `soak` |

What each layer holds: unit (crypto vectors, codecs, JSON/YAML including property tests), component (one NF against real sockets and
mock peers, config tests, CLI), integration (several NFs, real peer bytes), conformance (golden traces, schema validation of every
payload, the matrix), fuzz (replay drivers; libFuzzer targets in CI), perf (1,000 vectors/s gate), soak (mixed load with the UDR
killed and restarted).

## Conformance matrix
`docs/conformance/phase1-2-matrix.json` ... `phase5-matrix.json`: procedure -> clause -> test -> status. `python tools/check/check_matrix.py --ctest-list build/ctest-list.txt`
fails when a cited test, function or clause (checked against the pinned specification text) does not exist.

## Dashboard
`python3 tools/docs/gen_dashboard.py` (WSL, after a regression run) writes `build/dashboard/index.html`: one self-contained page with the
reference-point map, NF explorer (real route tables, files, coverage, metrics, configs, algorithm walk-throughs), decoded procedure
traces (real Open5GS/UERANSIM captures decoded by our own NGAP/NAS codecs, plus the JSON our NFs emit), the matrix, quality figures
and the roadmap. It needs `g5c-inspect` (built with the tree) and nothing outside the standard library.

## SMF specifics
The end-to-end test (`smf_e2e`) runs the UDR, UDM, PCF, the real UPF runtime (PFCP and GTP-U over loopback sockets, a datagram socketpair as N6), this SMF,
a scripted AMF and a scripted gNB in one process: establishment with a GBR voice rule, activation, AN release and service request, UE-requested release,
replacement, refusals, an AMF that refuses the transfer, pool exhaustion, the UPF stopped and restarted, 8 threads of session cycles. It runs under
ASan/UBSan and ThreadSanitizer. `smf_units` checks the building blocks byte for byte and feeds the generated N4 messages to the UPF engine.
`tools/diff/pfcp_diff.py --smf` compares Open5GS's SMF with ours (same UPF, same scenario); regenerate our capture with
`OUR_SMF=1 OUR_UDM=1 OUR_PCF=1 OUR_UPF=1 deploy/oracle/scenario.sh s3` then `scripts/save_golden.sh s3 s3_our_smf_our_upf_open5gs_amf_ueransim.pcapng`.
Seeds for `fuzz_smf` come from `tools/gen/gen_smf_fuzz_seeds.py`; the matrix is generated by `tools/gen/gen_phase4_matrix.py`. The PCF-push scenario against our SMF is
`OUR_SMF=1 OUR_UDM=1 OUR_PCF=1 OUR_UPF=1 deploy/oracle/scenario.sh s4`; UPF-restart, SMF-restart and discovery cases run in `smf_e2e` (about 10 s).

## AMF specifics
`amf_units` checks the building blocks byte for byte (5GMM messages, GPRS timers, the NAS COUNT estimation across the 8-bit wrap, the NH chain, algorithm
selection, maps, configuration). `amf_e2e` runs the UDR, UDM, the AUSF shim, PCF, the real UPF runtime, the SMF and this AMF in one process with scripted gNBs
(real SCTP on loopback, several at a time) and scripted UEs that derive KAMF, the NAS keys and KgNB on their own: NG Setup refusals, registration with a SUCI and
with a 5G-GUTI, authentication failures and resynchronisation, a PDU session with traffic through the UPF and a policy push, idle mode, service request with the
ciphered container, paging and its failure, identification, network-initiated de-registration and configuration update, association loss and NG Reset, event
exposure, SBI errors, Xn path switch (NH chain), N2 handover with cancellation and failure, algorithm negotiation, uplink MAC / replay, timer expiry (4
retransmissions then abort), implicit de-registration, persistence across a restart (about 60 s plain; it also runs under ASan/UBSan and ThreadSanitizer).
`fuzz_replay_amf` feeds the golden NGAP PDUs raw and with the NAS wrapped in a valid protected envelope of a registered UE, plus SBI bodies for every route; seeds
come from `tools/gen/gen_amf_fuzz_seeds.py`. The matrix is generated by `tools/gen/gen_phase5_matrix.py`.
Real peers: `OUR_AMF=1 deploy/oracle/scenario.sh s2|s3` (UERANSIM against our AMF, everything else Open5GS), and with `OUR_UDM=1 OUR_PCF=1 OUR_UPF=1 OUR_SMF=1`
added, s3 / s4 / s5 (s5: the gNB releases the UE context, the UE returns with a service request and pings again). `tools/diff/amf_diff.py` compares the NGAP
sequence and information elements of Open5GS's AMF and ours for the same scenario (`ngap_differential_amf`; regenerate our capture with
`OUR_AMF=1 deploy/oracle/scenario.sh s3` then `scripts/save_golden.sh s3 s3_our_amf_open5gs_core_ueransim.pcapng`).

## UPF specifics
`tools/diff/pfcp_diff.py` compares the same Open5GS SMF against Open5GS's UPF and against ours (golden captures `s3_*`); regenerate our capture with
`OUR_UPF=1 OUR_UDM=1 OUR_PCF=1 deploy/oracle/scenario.sh s3` then `scripts/save_golden.sh s3 s3_our_upf_open5gs_smf_ueransim.pcapng`.
Real-message vectors are generated by `tools/gen/gen_pfcp_vectors.py`, `gen_gtpu_vectors.py` and `gen_upf_fuzz_seeds.py`. Benchmarks are opt-in:
`G5C_PERF=1 ~/g5c-cbuild/plain/nf/upf/bench_upf` (engine) and `bench_upf_io` (runtime over real sockets). A longer fuzz campaign:
`G5C_FUZZ_MUTATIONS=150000 ~/g5c-cbuild/asan/fuzz/replay_upf tests/fixtures/fuzz/upf_seed.hex`.

## System tests on real processes (Phase 6)

| Command | What it does |
|---|---|
| `bash deploy/run/g5c-cluster.sh ns load <ues> [gnbs] [waves]` | the daemons as separate processes in a private user + network namespace (no privileges), driven by `nf/amf/tests/load_core.c`: every UE registers with 5G-AKA, establishes a PDU session and de-registers; UE-context / SMF-session / UPF-session counts are read from `/metrics` and must return to where they started |
| `... ns chaos <ues> <seconds>` | the same load while random functions are killed (SIGKILL) and restarted; failures are counted, a hang is a failure, and a clean recovery wave of new UEs must then pass |
| `... ns soak <ues> <seconds>` | waves back to back; the RSS of every function after the last wave must not be far above the second (a 72 hour run is `ns soak 500 259200`) |
| `G5C_LOAD_UES=10000 G5C_LOAD_GNBS=32 nf/amf/load_core` | the same load with the functions in one process (also under ASan: `G5C_LOAD_CHECK_MEM=0`) |

`ctest` registers `load_core_small`, `cluster_load`, `cluster_chaos` and `cluster_soak` (the cluster ones report SKIPPED where user namespaces are unavailable).
`scripts/g5c_regress.sh` runs a 2,000-UE cluster load and a 30 s chaos run and puts the result in its summary. Results and the bugs this found:
docs/history/phase6-baseline.md. Matrix: docs/conformance/phase6-matrix.json.
